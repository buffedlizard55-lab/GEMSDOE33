3. Addressing the Portal Range Error: [0, 1] Validation Without Human Intervention

Root Cause & Dual-Variant Packaging (submission_writer.py):

  1. In-Footprint Float32 Sentinel Contamination (IR-33-NODATA-01): In training_features.tif, 3,061 cells inside the active 5,167,373-cell template footprint carry the raw float32 nodata sentinel -3.4028235e+38 (`3,073` in band 6 tc). Any pipeline that feeds unmasked float32 bands into a linear/tree predictor without replacing sentinels can emit negative or NaN values inside the active footprint.
  2. Outside-Footprint Whole-Array Range Check: Outside the 5,167,373-cell footprint, sample_submission.tif has 7,111,787 cells set to NaN. In NumPy, np.nan >= 0.0 and np.nan <= 1.0 evaluate to False. If a portal validator checks np.all((arr >= 0.0) & (arr <= 1.0)) on the raw 3730 × 3292 array before masking to the footprint, any -nan.tif file will fail with a range error. Notably, our byte-level audit (`evidence/focus_sites_forensic_20261025.json`) confirmed that both GEMSDOE32 (h33-h33-2-b2-...-zeros.tif, 0.2778) and GEMSDOE36 (anderson-geothermal-pinn-38854-zeros.tif, 0.2756) used the all-finite -zeros.tif convention (`0.0` outside footprint, nodata=None).
  3. Automated Fail-Closed Guard: submission_writer.py refuses to write any raster with non-finite or out-of-range values inside the footprint, writes both -zeros.tif (whole-array finite in [0.0, 1.0]) and -nan.tif (NaN outside footprint), and re-opens the written files on disk with scripts/validate_submission.py.
